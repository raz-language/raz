## Consensus-visible invariants

- All arithmetic uses two-complement 64-bit register values; wrap/trap behavior is instruction-specific below.
- Branch targets are canonical instruction indices inside the current function.
- References are VM handles/offset identities, never host pointers.
- Invalid references, bounds violations, invalid calls, explicit `trap`, and specified arithmetic faults fail deterministically.
- `MEM_COPY` is overlap-safe and validates the complete source and destination ranges before mutation.
- Slice operations validate the slice length before resolving the element reference.
- RXE feature bits must equal the exact union required by the final opcode stream.
- Callable selectors are recomputed from name hash + ABI + complete parameter/return metadata; selector collisions are invalid.
- Export records must match their target callable descriptors and remain canonically selector-sorted.
- Canonical basic-block metadata must exactly partition functions and contain only in-function successors.
- Serialized RXE must pass independent decode + semantic validation + byte-identical re-encode.

## Decoder trust boundary

The independent Raz decoder must validate, from serialized bytes alone: section geometry, canonical reserved fields, opcode/register validity, exact feature bitmap, aggregate-layout ranges, signature ranges, recomputed callable selectors, export identity/order, and block partition/successor legality. The production C loader must implement the same consensus-visible checks independently.

## Version rule

Changing any opcode behavior above requires a new **RXE ISA version**. Changing only the self-describing container layout requires a new **RXE format version**. Compiler optimization and decoded µop/superinstruction changes do not change ISA version when canonical RXE behavior remains identical.
